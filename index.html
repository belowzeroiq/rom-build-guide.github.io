Build a custom ROM for the Redmi Note 12 4GBuat custom ROM untuk Redmi Note 12 4G

A start-to-finish path from a rented build server to a booting LineageOS-based build for the Snapdragon 685 (bengal) devices topaz and tapas: server, sources, device tree, blobs, kernel, flashing and debugging.Panduan dari awal sampai akhir, dari server build sewaan hingga build berbasis LineageOS yang berhasil booting untuk perangkat Snapdragon 685 (bengal) topaz dan tapas: server, source, device tree, blob, kernel, flashing, dan debugging.

OverviewIkhtisar

Topaz and tapas are the two codenames of the Redmi Note 12 4G. They share one SoC and one kernel, so most ROM projects keep a shared tree and add small per-variant differences. Check which one your phone reports before you start, because blobs and overlays are matched to it.Topaz dan tapas adalah dua codename dari Redmi Note 12 4G. Keduanya memakai SoC dan kernel yang sama, jadi kebanyakan proyek ROM menyimpan satu tree bersama dan menambahkan perbedaan kecil per varian. Periksa dulu varian mana yang dilaporkan ponselmu sebelum mulai, karena blob dan overlay disesuaikan dengannya.

The short routeJalur singkat

This is the workflow the author uses on a rented build server. The sections after it explain each step in more depth, for a first build or when something goes wrong.Ini alur kerja yang dipakai penulis di server build sewaan. Bagian-bagian setelahnya menjelaskan tiap langkah lebih dalam, untuk build pertama atau saat ada masalah.

  1. Rent a build server that is already set up for custom ROM building, so you install nothing yourself. The author recommends ServerHive, found on Telegram. It offers low, mid and high core plans.Sewa server build yang sudah disiapkan untuk build custom ROM, jadi kamu tidak perlu menginstal apa pun sendiri. Penulis merekomendasikan ServerHive, yang bisa ditemukan di Telegram. Tersedia paket core rendah, menengah, dan tinggi.
  2. Log in to the server over SSH. Start a tmux session so a dropped connection does not kill a long build.Login ke server lewat SSH. Mulai sesi tmux agar koneksi yang terputus tidak mematikan build yang panjang.
    SHELL
    ssh user@your-server
tmux new -s rom
  3. Create a Google source password. Sign in at android.googlesource.com, click Generate password, copy the command it shows, and paste it into the server's terminal. It saves your credentials so syncing is not rate limited.Buat password Google source. Login di android.googlesource.com, klik Generate password, salin perintah yang muncul, lalu tempel ke terminal server. Perintah ini menyimpan kredensialmu sehingga sinkronisasi tidak terkena rate limit.
  4. Set your git name and email.Atur nama dan email git.
    SHELL
    git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
  5. Pick an AOSP-based ROM source. For example LineageOS. Open its repository and find the repo init line for your branch.Pilih source ROM berbasis AOSP. Misalnya LineageOS. Buka repositorinya dan cari baris repo init untuk branch-mu.
  6. Run repo init with the ROM's own command, and add --depth=1 for a shallow clone that saves space.Jalankan repo init dengan perintah dari ROM tersebut, lalu tambahkan --depth=1 untuk shallow clone yang menghemat ruang.
    SHELL

  7. Clone your local manifest into .repo/local_manifests. It lists your device, vendor and kernel trees.Clone local manifest-mu ke .repo/local_manifests. Isinya daftar tree device, vendor, dan kernel.
    SHELL
    git clone https://github.com/YOUR_ORG/local_manifests -b BRANCH .repo/local_manifests
  8. Sync with the command the ROM's manifest page gives. A typical one:Sync dengan perintah dari halaman manifest ROM. Contoh umumnya:
    SHELL
    repo sync -c --no-tags --no-clone-bundle -j$(nproc --all) --force-sync
  9. Generate private keys in vendor/lineage-priv/keys with ./keys.sh. Keep that folder out of git and back it up. If you lose it, or change keys later, users must wipe data to update.Buat private key di vendor/lineage-priv/keys dengan ./keys.sh. Jangan masukkan folder itu ke git dan simpan cadangannya. Jika hilang, atau key diganti nanti, pengguna harus wipe data untuk update.
    SHELL
    cd vendor/lineage-priv/keys
./keys.sh
cd ~/android/lineage

    SHELL
    . build/envsetup.sh
  11. Choose the target with lunch, breakfast or brunch. LineageOS uses lunch in this flow, and the release part of the name depends on the branch.Pilih target dengan lunch, breakfast, atau brunch. LineageOS memakai lunch pada alur ini, dan bagian rilis pada namanya bergantung pada branch.
    SHELL
    lunch lineage_topaz-bp2a-userdebug
  12. Build the flashable zip.Build zip yang siap di-flash.
    SHELL
    mka bacon -j$(nproc --all)
  13. Wait for the build to finish. The zip lands in out/target/product/topaz/.Tunggu build selesai. Zip-nya ada di out/target/product/topaz/.
  14. Flash. See the flashing section for the recovery and sideload steps.Flash. Lihat bagian flashing untuk langkah recovery dan sideload.

Before you startSebelum mulai

  • A rented build server. A server already set up for custom ROM building, such as ServerHive, supplies the disk, memory and tools. Pick a plan by core count (see the build server section).Server build sewaan. Server yang sudah disiapkan untuk build custom ROM, seperti ServerHive, menyediakan disk, memori, dan tool-nya. Pilih paket berdasarkan jumlah core (lihat bagian server build).
  • A second way to get help. Keep a copy of the stock fastboot ROM for your region. It is the way back from a bad flash.Jalan pulang cadangan. Simpan salinan stock fastboot ROM untuk regionmu. Ini jalan kembali jika flash gagal.
  • An unlocked bootloader. This guide assumes your phone's bootloader is already unlocked, because flashing needs it. Back up your data first, since flashing a ROM wipes it.Bootloader yang sudah terbuka. Panduan ini mengasumsikan bootloader ponselmu sudah di-unlock, karena flashing membutuhkannya. Cadangkan datamu terlebih dulu, karena flash ROM akan menghapusnya.
  • Know your branch. Pick the Android version first (for example LineageOS 23.0 for Android 16). Device tree, vendor blobs and kernel must all target the same one.Tentukan branch-mu. Pilih versi Android lebih dulu (misalnya LineageOS 23.0 untuk Android 16). Device tree, vendor blob, dan kernel semuanya harus menargetkan versi yang sama.
Heads upFlashing can brick a phone. Never flash partitions you cannot name, and never flash a firmware package built for a different codename.PerhatianFlashing bisa membuat ponsel brick. Jangan pernah flash partisi yang tidak kamu kenali namanya, dan jangan flash paket firmware yang dibuat untuk codename lain.

Use a rented build serverPakai server build sewaan

Skip building your own machine. Rent a server that is already set up for custom ROM building, with the packages, the repo tool and ccache in place. ServerHive is one such service, and it offers low, mid and high core plans.Lewati urusan membangun mesin sendiri. Sewa server yang sudah disiapkan untuk build custom ROM, lengkap dengan paket, tool repo, dan ccache. ServerHive adalah salah satu layanannya, dengan paket core rendah, menengah, dan tinggi.

Choosing a planMemilih paket

More cores shorten the first full build the most. Later builds are much quicker on any plan once ccache is warm, so a lower plan can be enough if you keep rebuilding the same device. If you build several ROMs or branches, a higher plan pays off sooner.Core yang lebih banyak mempercepat build penuh pertama paling besar. Build berikutnya jauh lebih cepat di paket mana pun begitu ccache terisi, jadi paket yang lebih rendah bisa cukup jika kamu sering membangun ulang device yang sama. Jika kamu membangun beberapa ROM atau branch, paket yang lebih tinggi lebih cepat terasa manfaatnya.

Sync the sourcesSinkronkan source

Initialize the LineageOS manifest for your branch, then add your device repositories through a local manifest so they survive every repo sync.Inisialisasi manifest LineageOS untuk branch-mu, lalu tambahkan repositori device lewat local manifest agar tetap ada setiap kali repo sync.

You can write it as a file there, or keep it in its own git repository and clone it into that folder (see the short route). The device treeDevice tree

If you are porting, start from a working tree for the same SoC and the same Android generation, then move it forward one change at a time. Moving across two Android versions in one step is how trees end up with a hundred errors and no clue where they started.Jika kamu melakukan porting, mulailah dari tree yang sudah berjalan untuk SoC dan generasi Android yang sama, lalu majukan satu perubahan demi satu perubahan. Melompati dua versi Android sekaligus adalah cara tree berakhir dengan seratus error tanpa petunjuk dari mana semuanya bermula.

Pick one PowerHALPilih satu PowerHAL

Older trees ship the QTI performance HAL with powerhint.xml. Newer ones use the AOSP libperfmgr PowerHAL with powerhint.json. Choose one. If both are present, two services write to the same GPU frequency files at runtime and the phone gets unpredictable. When you switch, remove the old HAL's blobs from the vendor tree too.Tree lama membawa HAL performa QTI dengan powerhint.xml. Yang lebih baru memakai PowerHAL AOSP libperfmgr dengan powerhint.json. Pilih salah satu. Jika keduanya ada, dua layanan menulis ke file frekuensi GPU yang sama saat runtime dan perilaku ponsel jadi tidak bisa ditebak. Saat berpindah, hapus juga blob HAL lama dari vendor tree.

Pure AOSP on a Lineage treeAOSP murni di atas Lineage tree

Lineage device trees depend on Lineage-only pieces such as vendor/lineage inherits and the lineage_ product prefix. To build plain AOSP, rename the product file, replace the Lineage inherits in device.mk, edit AndroidProducts.mk to match, and remove any module that only exists in Lineage repositories.Device tree Lineage bergantung pada bagian khusus Lineage seperti inherit vendor/lineage dan prefiks produk lineage_. Untuk membangun AOSP murni, ganti nama file produk, ganti inherit Lineage di device.mk, sesuaikan AndroidProducts.mk, dan buang modul yang hanya ada di repositori Lineage.

Vendor blobsVendor blob

The camera, modem, Wi-Fi, audio and GPU stacks need Xiaomi's closed-source files. The example manifest already checks out a vendor tree that contains them, so you only need to extract when you refresh or add blobs. Extract from a stock ROM that matches the firmware on the phone.Stack kamera, modem, Wi-Fi, audio, dan GPU membutuhkan file closed-source dari Xiaomi. Manifest contoh sudah men-checkout vendor tree yang berisi file-file itu, jadi kamu hanya perlu mengekstrak saat memperbarui atau menambah blob. Ekstrak dari stock ROM yang cocok dengan firmware di ponsel.

Kernel

Stock runs a GKI 5.15 kernel with vendor modules loaded on top. The kernel image and the modules must agree on the same kernel module interface (KMI), so you have two safe choices.Stock menjalankan kernel GKI 5.15 dengan modul vendor dimuat di atasnya. Image kernel dan modul harus sepakat pada kernel module interface (KMI) yang sama, jadi ada dua pilihan aman.

  • Use the prebuilt kernel and modules. The fastest way to a first boot. Ship the kernel image, then the .ko files into the ramdisk or vendor partitions where the board config expects them.Pakai kernel dan modul prebuilt. Cara tercepat menuju boot pertama. Masukkan image kernel, lalu file .ko ke ramdisk atau partisi vendor sesuai yang diharapkan board config.
  • Build the kernel and modules from source. Required for custom features. Build the GKI image and every vendor module from the same checkout, with the same toolchain and config.Build kernel dan modul dari source. Diperlukan untuk fitur kustom. Build image GKI dan setiap modul vendor dari checkout yang sama, dengan toolchain dan config yang sama.

If you move a device tree between GKI generations (for example from the 6.12 line back to 5.15), expect to revisit BoardConfig.mk kernel settings and rebuild every out-of-tree module. Blobs built for the newer line often refuse to work on the older kernel, so check that before you commit to a rollback.Jika kamu memindahkan device tree antar generasi GKI (misalnya dari jalur 6.12 kembali ke 5.15), bersiaplah meninjau ulang pengaturan kernel di BoardConfig.mk dan membangun ulang setiap modul out-of-tree. Blob yang dibuat untuk jalur lebih baru sering menolak bekerja di kernel yang lebih lama, jadi periksa dulu sebelum memutuskan rollback.

Release builds and signingBuild rilis dan signing

Test builds are signed with the public test keys. Before you hand a build to anyone else, generate your own keys, keep them private and out of git, and sign every release with them.Build uji ditandatangani dengan test key publik. Sebelum menyerahkan build ke orang lain, buat key sendiri, jaga kerahasiaannya dan jangan masukkan ke git, lalu tanda tangani setiap rilis dengan key itu.

If your ROM source includes vendor/lineage-priv/keys/keys.sh, run it once to generate the key set, as in the short route. The steps below are the manual route, for sources that do not ship that script.Jika source ROM-mu menyertakan vendor/lineage-priv/keys/keys.sh, jalankan sekali untuk membuat set key, seperti pada jalur singkat. Langkah di bawah adalah cara manual, untuk source yang tidak menyertakan script itu.

  1. Create the platform, shared, media and releasekey keys with the make_key script from development/tools.Buat key platform, shared, media, dan releasekey dengan script make_key dari development/tools.
  2. Create an AVB key and point BOARD_AVB_KEY_PATH at it so avbtool signs the boot chain.Buat key AVB dan arahkan BOARD_AVB_KEY_PATH ke sana agar avbtool menandatangani rantai boot.
  3. Build the target-files package, re-sign it with sign_target_files_apks, then produce the OTA with ota_from_target_files.Build paket target-files, tanda tangani ulang dengan sign_target_files_apks, lalu hasilkan OTA dengan ota_from_target_files.

If you flash an AVB-signed build with a custom key, the bootloader must trust that key. Test the whole chain on one phone before you publish.Jika kamu mem-flash build bertanda tangan AVB dengan key kustom, bootloader harus mempercayai key itu. Uji seluruh rantai di satu ponsel sebelum dipublikasikan.
